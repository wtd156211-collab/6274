# 并发度自适应调整（从 0 实现）

起始环境里只有本说明、`samples/**` 与 `.gitignore`：引擎、页面、测试都新写。Python 3.13、只用标准库；
交付物是引擎（库 + 命令行入口 `gate.py`）和它生成的 `concurrency.html`（单文件、双击即开），测试用 unittest。

## 一、范围

做：一个并发度调节器。它读一份**注入的调用时序脚本**（每个调用的到达时刻、耗时、结果都写死在脚本里），按
当前并发度决定哪些调用开工、哪些先排队，按结果调整并发度，输出一条逐行可核的轨迹；再把轨迹渲染成能复盘
那次雪崩的页面。

不做：真实网络请求与重试、读写 `samples/**`（只读）、读系统时钟或依赖真实调度、线程与协程、第三方依赖与
构建步骤、监控告警，也不把期望文件当成输入。

## 二、口径与公式

时刻与耗时一律用整数毫秒。

- **并发度 `n`**：同一时刻最多有多少个调用在飞。`初始` 是开局值，全程必须落在脚本头给的 `[下限, 上限]` 内。
- **成功**：开工的调用跑完且结果为 `ok` → `n ← min(上限, n + 1)`。
- **失败**：跑完且结果为 `err` → `n ← max(下限, n // 2)`（整除，向下取整）。
- **冷却**：距上一次「并发度真的变了」不足 `冷却` 毫秒时，任何结果都不调整（开局的第一次不受限）；`n` 没
  变不算一次调整，也不刷新冷却时刻。
- **放行与排队**：调用按脚本次序到达；到达时在飞数 `< n` 就立即开工（开工时刻 = 到达时刻），否则排到队尾；
  只要在飞数 `< n`，队首就开工（开工时刻 = 当时时刻）。先进先出。
- **放弃**：调用在 `到达时刻 + 超时` 仍未开工，就从队列里摘掉、不再开工；放弃不触发调整（只有跑完的调用
  才提供反馈），已开工的调用不判超时，按脚本耗时结算。
- **指标**：`截止` = 最后一个事件结算的时刻；`吞吐 = 成功 * 1000 / 截止`（每秒成功数）；
  `错误率 = (失败 + 放弃) * 100 / 调用`（百分数）。两个数都用 Python 的 `f"{值:.3f}"` 输出。
- **理由**：触发这次调整的那条调用的结果：`成功` 或 `失败`。

## 三、状态机与数据结构

状态：`now`、`n`、在飞集合（要能取到最早结束时刻）、等待队列（先进先出）、上次调整时刻、统计量；调用
编号按脚本里的出现次序从 1 编。

主循环（同一时刻的事件次序写死）：

1. 补位：只要队列非空且在飞数 `< n`，队首开工（开工时刻 = `now`，结束时刻 = `now + 耗时`）。
2. 下一个时刻 `T` 取三个候选的最小者：队首的放弃时刻、最早的在飞结束时刻、下一条未处理调用的到达时刻；
   三个都没有就结束。
3. `now = T`，处理这一时刻的全部事件，次序固定为 **放弃 → 结束 → 到达**；同类型内部按编号升序，每处理
   完一条就回到第 1 步补一次位，再处理同一时刻的下一条。

跑完后 `截止` = 主循环结束时的 `now`。样例里有上万次调用，别每次都扫全部调用。

## 四、输入输出与文件格式

下面这些文件都是 UTF-8 无 BOM、LF 换行、末行有换行。

**4.1 时序脚本 `samples/scripts/<名>.txt`**：`#` 开头是注释，空行忽略；第一条有效行是头，之后一行一个调用。

```
H|名=01-steady|初始=8|下限=1|上限=32|冷却=200|超时=2000
C|10|60|ok
C|20|60|ok
```

头里六个字段缺一不可。约束：`1 ≤ 下限 ≤ 初始 ≤ 上限`、`冷却 ≥ 0`、`超时 ≥ 1`、至少一条调用、到达时刻
非降且 ≥ 0、耗时 ≥ 1、结果只能是 `ok` 或 `err`；不满足即输入不可用。

**4.2 轨迹（`run` 的输出）**：由下面三类行组成，字段之间一个 `|`，顺序固定。

```
H|<名>|调用=<条数>|初始=<n>|下限=<n>|上限=<n>|冷却=<毫秒>|超时=<毫秒>
A|<时刻>|<编号>|<旧>|<新>|<成功|失败>
T|调用=<条数>|成功=<n>|失败=<n>|放弃=<n>|截止=<毫秒>|吞吐=<x.3f>|错误率=<x.3f>%|调整=<条数>|最低=<n>|最高=<n>|末值=<n>
```

`A` 行按时刻升序，没调整过就一条都没有，`调整` 就是它的条数；`成功 + 失败 + 放弃 = 调用`；`最低 / 最高
/ 末值` 都把初始值算进去，`末值` 是跑完时的 `n`。

**4.3 门槛 `samples/expected-metrics.txt`**：一行一个脚本，六行，顺序与样例编号一致。

```
<脚本名>|吞吐>=<x.3f>|错误率<=<x.3f>%|调整<=<条数>
```

**4.4 命令行**：在仓库根目录执行；`gate.py` 既是库也是入口，公开接口自定（写进模块 docstring）。

```
python gate.py run <脚本文件> <轨迹文件>
python gate.py report <轨迹文件> <页面文件>
```

诊断走 stderr；退出码 0 表示跑完，1 表示输入不可用（此时不写输出文件）。

**4.5 页面 `concurrency.html`**：`report` 只读轨迹文件，不读脚本、不重算。单文件 HTML、样式内联、无脚本、
无外部引用、双击即开，跑两遍逐字节相同；内嵌 `<pre id="trace">`，内容与轨迹文件逐字节相同（去掉末尾换行，
按 `&`→`&amp;`、`<`→`&lt;`、`>`→`&gt;` 转义）。页面上要有：

1. 并发度随时间的内联 SVG 台阶曲线，元素带 `data-kind="curve"`：横轴 `0..截止`，纵轴 `下限..上限`。
2. 竖线：每次调整后新值等于本轨迹 `最低` 的时刻带 `data-kind="trough"`，新值等于 `上限` 的时刻带
   `data-kind="peak"`；竖线上写清时刻与新值。
3. 调整列表：每条 `A` 行对应一项 `data-kind="adjust"`，写清时刻、编号、旧值→新值与原因。

## 五、性能与验收口径

规模：`06-scale` 有 12000 次调用，其余脚本 60–1200 次。

- 单条记录的处理摊到 `O(log 在飞数)` 以内；不许每次事件重扫全部调用。
- 时间（验收机：本机 CPython、单进程单线程、SSD）：`06-scale` 的 `run` ≤ 5 秒，其余脚本的 `run` ≤ 2 秒，
  任何 `report` ≤ 2 秒。
- 对拍（逐条可核）：`python gate.py run samples/scripts/<名>.txt var/<名>.txt` 的输出与
  `samples/expected/<名>.txt` 逐字节相同。
- 门槛：轨迹 `T` 行的吞吐、错误率、调整三项满足 `samples/expected-metrics.txt` 里该脚本那一行。
- 确定性：同一条命令跑两遍逐字节相同；不读系统时钟，结果只由脚本与本文口径决定。
- 测试：`python -m unittest discover -s tests` 全绿，只用标准库、只读 `samples/**`，测试自己写。

## 六、样例说明

`samples/scripts` 与 `samples/expected` 同名一一对应；括号里是 调用数 / 调整次数 / 吞吐 / 错误率 / 放弃数。

| 样例 | 场景与关键结果 |
| --- | --- |
| `01-steady` | 平稳期：全成功，并发度每 200 毫秒加 1 直到上限 32（500 / 24 / 98.814 / 0.000% / 0） |
| `02-burst` | 突发错误后恢复：3.0–3.6 秒连失败，并发度 23→11→5→2→1 见底后加回 32（1200 / 50 / 94.444 / 5.083% / 0） |
| `03-sticky` | 持续高错误：八成失败，并发度被压在下限附近 1–5 来回（800 / 49 / 13.800 / 82.750% / 115） |
| `04-flapping` | 频繁抖动：成功失败各半，冷却把调整次数按住（500 / 88 / 11.908 / 52.200% / 0） |
| `05-idle` | 长时间零负载：两段约 20 秒的空档里一次都不调整（60 / 3 / 1.490 / 0.000% / 0） |
| `06-scale` | 上万次调用：12000 次，含 150 连失败，在预算内跑完（12000 / 120 / 480.017 / 3.917% / 0） |

`samples/notes.md` 是现场记录（背景不是规格），冲突以本文件为准。
